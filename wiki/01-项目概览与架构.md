# 01 - 项目概览与架构

> 返回 [Wiki 首页](./README.md)

## 1. 项目定位

LocalDream-Web 是一个**本地自托管**的 Stable Diffusion 生图 Web 应用，采用前后端分离架构：

- **前端**（`web/src/`）：React 单页应用（SPA），负责生图参数编辑、模型/LoRA 管理、历史浏览等全部 UI 交互。
- **后端**（`web/backend/`）：FastAPI 服务，封装 Diffusers 推理管线，管理 GPU 显存、模型缓存、LoRA 生命周期与 SQLite 持久化。
- **特色**：通过 `torch-directml` 让 **AMD 显卡**（无需 CUDA）原生加速推理，并针对 RDNA 1 架构的 DirectML 算子缺陷内置了自动 CPU 回退补丁（详见 [06-DirectML兼容与显存管理](./06-DirectML兼容与显存管理.md)）。
- **扩展**：根目录的 `LocalDream-SD.json` 是一个可选的 SillyTavern 酒馆插件脚本，可调用本项目后端在聊天中直接生图。

## 3. 一次生图请求的完整链路

以「图像生成」页点击 **开始生成** 为例：

1. **GeneratePage.tsx** 收集参数 → 调用 `generateImage()`（[api.ts](../web/src/utils/api.ts)）
2. 前端 `fetch POST /api/generate`，建立 SSE 长连接
3. 后端 [routes/generate.py](../web/backend/app/routes/generate.py) 将请求转交给 `generate_image()` 异步生成器
4. **generator.py** 依次执行：
   - 速度预设（fast/balanced/quality）覆盖默认参数
   - 模型预热（首次加载 pipeline 并跑一次 64×64 推理；在线程池中执行，不冻结事件循环）
   - `_get_pipeline()` 命中 LRU 缓存或从磁盘加载 pipeline（按 `模型:模式:<LoRA组合>` 为缓存键；单文件 checkpoint 走 `from_single_file` 直载）
   - 装载/切换 LoRA 适配器（lora_manager）
   - 在线程池中运行 Diffusers 推理（全局推理锁串行化，并发请求排队），通过 `callback_on_step_end` 回调把进度与中间预览图推入 `asyncio.Queue`
   - **OOM 分级降级**：清缓存+卸载其它模型 → 关闭实时预览 → txt2img 自动降分辨率（每级发 `notice` 事件告知前端）
5. 事件以 `data: {...}\n\n` 格式流式推送（`started` → `progress`×N（可穿插 `notice`）→ `complete`/`error`）
6. 收到 `complete` 并**先发给客户端**后，后端把图片写入 `outputs/`、生成缩略图、插入 `history_items` 表
7. 前端解析 SSE，逐步更新进度条与预览图，完成后展示最终图像与耗时统计

### 关于 `_patch_transformers.py`

一个**独立的运维脚本**（非运行时依赖）：修复旧版 transformers `modeling_utils.py` 中 `safe_open(...).metadata()` 返回 `None` 导致 `metadata.get("format")` 崩溃的问题。脚本内硬编码了作者机器上的文件路径，仅用于一次性就地修补本机环境，其他环境需按需修改路径后手动运行。

### 关于 `test_vram.py`

VRAM 诊断脚本：验证 `torch_directml` 的 `memory_allocated()` / `get_device_properties()` 是否可用，用于排查显存查询失败问题。同样不参与服务运行。

## 5. 关键设计决策

| 设计 | 说明 | 收益 |
|------|------|------|
| **pipeline LRU 缓存（上限 2）** | 以 `模型ID:模式:<LoRA组合>` 为键缓存 Diffusers pipeline，超限逐出最旧 | 平衡模型切换速度与显存占用 |
| **LoRA 组合入缓存键** | 不同 LoRA 组合各占独立缓存项，切换组合即建新 pipeline 并立刻清理旧项 | 避免适配器状态污染与显存泄漏 |
| **SDXL 混合设备布局** | UNet 在 DML fp16（channels_last），文本编码器在 CPU，VAE 解码走 CPU fp32 | 绕开 RDNA 1 的 fp16 算子缺陷 |
| **推理放线程池 + asyncio.Queue** | 阻塞的 PyTorch 推理不卡事件循环，进度回调跨线程安全投递 | 单进程内实现 SSE 实时推送 |
| **SSE 而非 WebSocket** | 生图是单向服务端推送，SSE 足够且免握手协议 | 实现简单、兼容性好 |
| **图片走 base64** | 生成结果与预览均以 base64 内嵌 SSE/JSON 返回；原图另存 `outputs/` | 前端无需二次请求即可展示 |
| **SQLite + WAL** | 历史记录与设置本地持久化，WAL 模式提升并发读写 | 零部署成本 |
| **CORS 全开** | `allow_origins=["*"]`，前端 dev server 与后端可分机部署 | 局域网任意设备可访问 |

## 6. 页面与路由

| 路由 | 页面组件 | 功能 |
|------|---------|------|
| `/` | `ModelListPage` | 模型管理：列表、下载（HuggingFace）、删除、选择、卸载 |
| `/generate`、`/generate/:modelId` | `GeneratePage` | 生图主界面：txt2img / img2img / inpaint、LoRA、参数、预览 |
| `/history` | `HistoryPage` | 生图历史：分页缩略图墙、详情弹层、删除 |
| `/upscale` | `UpscalePage` | 超分辨率：上传图片 → RealESRGAN 4x 放大 |
| `/settings` | `SettingsPage` | API 地址、默认生图参数配置、后端健康检查 |

> `src/pages/Home.tsx` 为空占位组件，当前路由表中未使用。
