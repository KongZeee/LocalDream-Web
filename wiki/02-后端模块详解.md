# 02 - 后端模块详解

> 返回 [Wiki 首页](./README.md) | 上一章 [01-项目概览与架构](./01-项目概览与架构.md) | 下一章 [03-前端模块详解](./03-前端模块详解.md)

后端位于 `web/backend/`，采用 **路由层（routes）→ 服务层（services）→ 数据层（db/config）** 三层结构。入口为 [run.py](../web/backend/run.py)，应用装配在 [app/main.py](../web/backend/app/main.py)。

## 模块总览

| 模块 | 路径 | 职责 |
|------|------|------|
| 启动入口 | `backend/run.py` | 以 uvicorn 启动 FastAPI 应用 |
| 应用装配 | `app/main.py` | 创建 FastAPI 实例、CORS、lifespan 初始化数据库、注册 7 个路由 |
| 全局配置 | `app/config.py` | 读取环境变量，定义路径/端口/默认生图参数 |
| 数据库 | `app/db.py` | SQLite 连接工厂与建表脚本 |
| 生图路由 | `routes/generate.py` | `POST /api/generate`（SSE）、`GET /api/health` |
| 模型路由 | `routes/models.py` | 模型列表/预加载/卸载/下载/删除 |
| LoRA 路由 | `routes/loras.py` | LoRA 文件扫描列表 |
| 历史路由 | `routes/history.py` | 历史分页/图片服务/删除 |
| 设置路由 | `routes/settings.py` | KV 设置读写 |
| 系统路由 | `routes/system.py` | GPU/CPU 内存状态探测 |
| 放大路由 | `routes/upscale.py` | 图片 4x 超分 |
| **生图引擎** | `services/generator.py` | ⭐ 核心：pipeline 缓存/LRU/OOM 保护/DirectML 补丁/SSE 事件流 |
| LoRA 管理 | `services/lora_manager.py` | LoRA 适配器的加载/卸载/组合管理 |
| 模型管理 | `services/model_manager.py` | 本地模型扫描、HF 下载、预加载 |
| 历史服务 | `services/history.py` | 历史记录 CRUD 与图片落盘 |
| 超分服务 | `services/upscaler.py` | RealESRGAN 管线（含降级） |

## 1. run.py — 启动入口

```python
import uvicorn
from app.main import app
from app.config import HOST, PORT

if __name__ == "__main__":
    uvicorn.run(app, host=HOST, port=PORT, log_level="info")
```

默认监听 `0.0.0.0:8081`（可由环境变量覆盖，见 [08-部署与运行指南](./08-部署与运行指南.md)）。

## 2. app/main.py — 应用装配

**关键点：**

- `lifespan` 异步上下文管理器：应用启动时调用 `init_db()` 完成建表，退出时无需清理。
- **CORS 中间件全开**（`allow_origins=["*"]`、允许所有方法/头、携带凭证），使局域网内任意前端可直连后端。
- 注册 7 个子路由：`generate`、`upscale`、`models`、`history`、`settings`、`loras`、`system`。
- 根路径 `/` 返回服务名与版本（`Local Dream API v1.0.0`）。

## 3. app/config.py — 全局配置

**职责：** 集中管理所有可配置项，优先读环境变量，否则用默认值。

**关键常量：**

| 常量 | 环境变量 | 默认值 | 说明 |
|------|---------|--------|------|
| `DATA_DIR` | `LOCAL_DREAM_DATA_DIR` | `web/backend/data` | 数据根目录 |
| `MODELS_DIR` | `LOCAL_DREAM_MODELS_DIR` | `{DATA_DIR}/models` | SD 模型目录 |
| `OUTPUT_DIR` | `LOCAL_DREAM_OUTPUT_DIR` | `{DATA_DIR}/outputs` | 生成图输出目录 |
| `DB_PATH` | `LOCAL_DREAM_DB_PATH` | `{DATA_DIR}/localdream.db` | SQLite 路径 |
| `HOST` | `LOCAL_DREAM_HOST` | `0.0.0.0` | 监听地址 |
| `PORT` | `LOCAL_DREAM_PORT` | `8081` | 监听端口 |
| `MAX_CACHED_PIPELINES` | `LOCAL_DREAM_MAX_PIPELINES` | `2` | LRU 显存中最多驻留的 pipeline 数（16GB+ 显卡可调大） |

**默认生图参数：** `DEFAULT_STEPS=15`、`DEFAULT_CFG=7.0`、`DEFAULT_WIDTH/HEIGHT=512`、`DEFAULT_SCHEDULER="dpm"`、`DEFAULT_SPEED_MODE="balanced"`、内置负向提示词。

模块导入时即对 `DATA_DIR / MODELS_DIR / OUTPUT_DIR` 执行 `makedirs(exist_ok=True)`，保证目录一定存在。

## 4. app/db.py — 数据库层

**关键函数：**

| 函数 | 说明 |
|------|------|
| `get_db()` | 每次调用建立新的 aiosqlite 连接；设置 `row_factory=aiosqlite.Row`（支持按列名取值）；开启 `PRAGMA journal_mode=WAL`（并发读写优化）与 `foreign_keys=ON`。**调用方负责在 `finally` 中 `db.close()`** |
| `init_db()` | 执行建表脚本：`history_items`（历史记录）、`settings`（KV 设置）、`model_cache`（模型下载缓存）；并 `INSERT OR IGNORE` 写入默认设置行 |

> 采用"每操作一连接"的短连接模式而非连接池，配合 WAL 模式，对单机低并发场景足够简单可靠。

表结构详见 [05-数据存储设计](./05-数据存储设计.md)。

## 5. 路由层（routes/）

路由层只做：**参数校验（Pydantic）→ 调用 service → 包装响应/错误**，不含业务逻辑。

### 5.1 routes/generate.py — 生图路由

**`GenerateRequest`（Pydantic 请求模型）核心字段：**

| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `prompt` | str | 必填 | 正向提示词 |
| `negative_prompt` | str | `""` | 负向提示词 |
| `model_id` | str | 必填 | 模型 ID（本地目录名中 `--` 还原为 `/`） |
| `mode` | str | `"txt2img"` | `txt2img` / `img2img` / `inpaint` |
| `steps` / `cfg` / `seed` / `width` / `height` | int/float | 20 / 7.5 / 42 / 512 / 512 | 采样参数 |
| `scheduler` | str | `"dpm"` | 调度器键名（见 SCHEDULER_MAP） |
| `denoise_strength` | float | 0.6 | img2img/inpaint 去噪强度 |
| `image` / `mask` | str? | None | base64 参考图/蒙版 |
| `show_preview` / `preview_stride` | bool/int | True / 1 | 是否推送中间预览及推送间隔 |
| `speed_mode` | str | `"balanced"` | 速度预设（fast/balanced/quality） |
| `loras` | list[dict]? | None | LoRA 列表 `[{id, name, path, filename, weight}]` |

**`POST /api/generate`：** 返回 `StreamingResponse`（`text/event-stream`），内部 `event_stream()` 异步生成器逐条转发 `generate_image()` 产生的事件；收到 `complete` 事件时**先把结果发给客户端**，再调用 `add_history()` 落盘历史（失败仅打印日志，不影响生图结果）；任何异常转为 `{"type": "error"}` 事件。

**`GET /api/health`：** 返回服务状态、GPU 探测结果（复用 `system.get_gpu_info()`：CUDA 设备名 / DirectML 设备名 / CPU，不再硬编码）、当前已加载模型与模型目录。

### 5.2 routes/models.py — 模型路由

| 端点 | 逻辑 |
|------|------|
| `GET /api/models` | `get_models()`：**合并展示**本地扫描结果与 `model_cache` 下载/转换状态（磁盘存在即视为 ready）；附带默认模型设置 |
| `GET /api/models/loaded` | 当前显存中已加载的模型列表 + 最近使用的模型 |
| `POST /api/models/unload` | 卸载指定模型的所有 pipeline（含 `_empty_dml_cache()` 真正归还显存）；未加载返回 404 |
| `POST /api/models/unload-all` | 清空全部 pipeline 缓存 |
| `POST /api/models/{model_id:path}/preload` | 预加载模型到显存并**执行真实预热推理**（`:path` 转换器支持含 `/` 的 HF ID） |
| `POST /api/models/download` | 从 HuggingFace 下载模型（`DownloadRequest{model_id, model_type}`）；**立即返回**，下载在后台执行 |
| `POST /api/models/convert` | 把单文件 checkpoint 转换为 Diffusers 目录（`ConvertRequest{model_id}`）；**立即返回**，转换在后台执行 |
| `DELETE /api/models/{model_id:path}` | 删除本地模型（目录 rmtree / 单文件 unlink）及缓存记录 |

### 5.3 routes/loras.py — LoRA 路由

- `GET /api/loras`：完整 LoRA 元数据列表（id/名称/文件名/路径/大小）。
- `GET /api/loras/names`：轻量版（仅 id+name），供下拉框使用。

### 5.4 routes/history.py — 历史路由

- `GET /api/history?page=&page_size=`：分页历史。
- `GET /api/history/{id}/image` 与 `/thumbnail`：以 `Response(content=bytes, media_type="image/jpeg")` 直接回传图片二进制。
- `DELETE /api/history/{id}`：删除记录及磁盘图片。

### 5.5 routes/settings.py — 设置路由

- `GET /api/settings`：整表读出为 `{key: value}` 字典。
- `PUT /api/settings`：接受任意 dict，逐键 `INSERT OR REPLACE`（值统一 `str()` 存储）。

### 5.6 routes/system.py — 系统状态路由

**`SystemStatus` 响应模型：** `gpu_available`、`gpu_name`、`gpu_memory_used_mb/total_mb`、`cpu_memory_used_mb/total_mb`、`loaded_models`、`current_model`。

**探测优先级链（`_get_gpu_memory()` / `_get_cpu_memory()`）：**

1. **CUDA**：`torch.cuda` 可用则取显存统计（NVIDIA 路径）
2. **psutil**：CPU 内存（若安装）
3. **Win32 `GlobalMemoryStatusEx`**（ctypes 直接调 kernel32）：DirectML 无显存查询 API 时的系统内存兜底（仅 Windows 生效；DirectML 模式下 GPU 值实际返回的是**系统物理内存**）

`GET /api/system/status` 同时探测 GPU 名称：CUDA → `cuda.get_device_name`；否则若 `torch_directml` 可导入 → `"AMD GPU (DirectML)"`；否则 `"CPU"`。前端 `StatusBar` 每 5 秒轮询该端点。

### 5.7 routes/upscale.py — 超分路由

`POST /api/upscale`：**multipart 表单**（`image: UploadFile`、`model_id: str = "RealESRGAN_x4plus"`、`tile_size: int = 512`），校验 content-type 以 `image/` 开头后交由 `upscale_image()` 同步处理。

## 6. 服务层（services/）

### 6.1 services/generator.py — 生图引擎（核心模块）

这是全项目最核心的文件，集中了 **pipeline 缓存、调度器、速度预设、OOM 保护、DirectML 补丁、SSE 事件生成** 六大职责。

#### 模块级状态

| 名称 | 类型 | 说明 |
|------|------|------|
| `_pipelines` | `dict[str, pipe]` | pipeline 缓存，键为 `"{model_id}:{mode}"` 或含 LoRA 的 `"{model_id}:{mode}:<{lora组合}>"` |
| `_pipeline_lock` | `threading.RLock` | 保护缓存的所有读写。**必须可重入**：`_get_pipeline` 持锁加载过程中会调用 `_cleanup_stale_lora_pipelines` 再次拿锁（普通 Lock 会死锁） |
| `_inference_lock` | `threading.Lock` | **GPU 推理串行化**：Diffusers pipeline 非线程安全，且并发推理必炸显存；并发请求在此排队（排队时客户端收到 notice 提示） |
| `_dml_device` | torch device | 懒初始化的 DirectML 设备 |
| `_warmed_up` | `set[str]` | 已预热模型集合 |
| `_MAX_CACHED_PIPELINES` | int | LRU 上限（默认 2，环境变量 `LOCAL_DREAM_MAX_PIPELINES` 可调） |
| `_pipeline_access_order` | `list[str]` | 访问顺序表（旧 → 新），LRU 逐出依据 |
| `_cpu_vae_cache` | AutoencoderKL | SDXL 专用的 CPU fp32 VAE（懒加载，模型 `madebyollin/sdxl-vae-fp16-fix`） |
| `_cpu_vae_cache_sd15` | `dict[model_id, VAE]` | SD 1.5 预览解码用的 CPU fp32 VAE 副本缓存（避免每步预览把 VAE 在 DML↔CPU 间搬运） |
| `_OOM_PATTERNS` | tuple[str] | OOM 错误签名（`not enough gpu video memory` / `out of memory` / `0x8007000e` / `e_outofmemory` / `video memory`），`_is_oom()` 大小写不敏感宽匹配 |

#### 常量映射

```python
SCHEDULER_MAP = {
    "dpm":         DPMSolverMultistepScheduler,
    "dpm_karras":  lambda c: DPMSolverMultistepScheduler.from_config(c, use_karras_sigmas=True),
    "euler":       EulerDiscreteScheduler,
    "euler_karras":lambda c: EulerDiscreteScheduler.from_config(c, use_karras_sigmas=True),
    "euler_a":     EulerAncestralDiscreteScheduler,
    "lcm":         LCMScheduler,
}

SPEED_PRESETS = {
    "fast":    {"steps": 10, "cfg": 4.0, "scheduler": "dpm"},
    "balanced":{"steps": 15, "cfg": 7.0, "scheduler": "dpm"},
    "quality": {"steps": 25, "cfg": 7.5, "scheduler": "dpm_karras"},
}
```

> `SPEED_PRESETS` 的取值策略：仅当调用方未显式指定（`steps<=0`、`cfg<=0` 或调度器为默认 `dpm`）时才用预设值覆盖，前端切换速度档会直接下发预设值。

#### 关键函数

**`async generate_image(...) -> AsyncGenerator[dict]`** — 生图主流程（SSE 事件源）：

1. 判定 `is_sdxl = _is_sdxl_model(model_id)`（名字含 "xl" → 读 `model_index.json` 的 `_class_name` → 单文件 checkpoint 则 peek safetensors 头部 key，见 model_manager 的 `detect_sdxl`；Anima/Pony 等"无名 XL"模型也能正确识别）
2. 应用速度预设（仅补默认值）
3. `_warmup_model()` **在线程池中执行**（不冻结事件循环）：首次遇到该模型时跑一次 64×64、2 步、`output_type="latent"` 的空推理，触发 shader 编译等一次性开销
4. `_get_pipeline()` 取管线 → `_set_scheduler()` 切调度器 → `torch.manual_seed(seed)`
5. base64 解码参考图/蒙版（img2img / inpaint 时以 **LANCZOS** resize 到目标分辨率）
6. 构造 `kwargs` 并注册 **`callback_on_step_end` 回调**：每步把 `{type: "progress", step, total_steps}`（可选携带中间预览 base64）通过 `loop.call_soon_threadsafe()` 线程安全地投入 `asyncio.Queue`；预览解码使用 `_generate_preview(pipe, latents, is_sdxl, model_id)` —— SDXL 与 SD1.5 均使用**缓存的 CPU fp32 VAE 副本**，不再搬运 live VAE
7. `loop.run_in_executor(None, run_inference)` 在**线程池**中执行阻塞推理；主协程 `while not future.done()` 轮询队列转发事件（0.5s 超时避免忙等）；推理本身持有 `_inference_lock`（GPU 串行化），若锁被占用先发 `notice` 事件告知客户端已排队
8. **OOM 分级降级阶梯**（`run_inference` 内，最多 3 次恢复尝试）：
   - **L1**：`_empty_dml_cache()` + `_unload_other_models()`（其它模型的缓存 pipeline 常是显存元凶）→ 重试
   - **L2**：摘除 `callback_on_step_end`（关闭实时预览）→ 重试
   - **L3**：txt2img 分辨率 ×0.75（对齐到 8 的倍数，下限 256）→ 重试
   - 每级降级通过 `notice` 事件告知前端；全部失败产出可操作的错误消息。img2img/inpaint 不做 L3（尺寸跟随参考图）
9. SDXL 特殊路径：`output_type="latent"` 返回潜变量，用 `_get_cpu_vae_fp32()` 的 CPU VAE 解码（避开 DML 解码崩溃/OOM）
10. 最终 yield `complete` 事件（图片 base64、seed、**实际输出尺寸**（可能被 L3 降级过）、总耗时 `generation_time_ms`、首步耗时 `first_step_time_ms`）

事件序列：`started` → (`notice`)→ `progress` × N（可穿插 `notice`）→ `complete | error`

**`_get_pipeline(model_id, mode, is_sdxl, loras)` — pipeline 工厂 + LRU 缓存：**

1. 计算 cache key（含按 id 排序的 LoRA 组合标签）
2. 命中缓存 → `_touch()` 更新 LRU 顺序并返回
3. 未命中 → `_evict_lru_unlocked()` 先腾出缓存位（逐出最旧直到数量 < 上限）
4. 定位模型路径：本地 `{MODELS_DIR}/{model_id.replace("/", "--")}` 存在则用本地，否则视为 HF repo ID 在线加载；**若本地路径是文件（单文件 checkpoint `.safetensors`/`.ckpt`）走 `pipe_cls.from_single_file()` 直接加载**（内存中转换，每次冷加载较慢——常用模型建议先 `POST /api/models/convert` 拆包）
5. 按模型类型与模式选择 6 个 pipeline 类之一（SD/SDXL × txt2img/img2img/inpaint）
6. **SDXL 专属布局**：换 fp16-fix VAE → 文本编码器移 CPU → UNet 移 DML fp16 + channels_last → VAE 移 DML fp16（失败则回退 CPU fp32）→ 安装 Embedding/Linear/GroupNorm/Conv2d 补丁 → 开启 VAE slicing/tiling + attention slicing("max")
7. **SD 1.5 布局**：整个 pipeline 移 DML，开启 VAE slicing/tiling + attention slicing
8. 给默认调度器打 step 补丁 → 存入缓存 → `mark_pipeline()` 打 LoRA 标签 → `apply_loras()` 装载 LoRA → `_cleanup_stale_lora_pipelines()` 立即清理同模型同模式下的其它 LoRA 组合缓存 → `_touch()` 返回

**显存管理函数组：**

| 函数 | 说明 |
|------|------|
| `_touch(key)` | 把键移到 LRU 顺序表末尾（最近使用） |
| `_evict_lru_unlocked()` / `_evict_lru()` | 持锁逐出最旧 pipeline 直到数量 < 上限；**逐出后调用 `_empty_dml_cache()` 真正把显存还给驱动**（`del` + `gc.collect()` 只释放到分配器缓存池） |
| `_cleanup_stale_lora_pipelines(model_id, mode, fresh_key)` | 切换 LoRA 组合后立即驱逐旧的 LoRA pipeline（前缀 `{model_id}:{mode}:<` 且 ≠ 新键）+ `_empty_dml_cache()` |
| `_unload_other_models(keep_model_id)` | OOM 恢复 L1 使用：驱逐所有非当前模型的缓存 pipeline + `_empty_dml_cache()` |
| `_empty_dml_cache()` | 依次尝试 `torch.cuda.empty_cache()` / `torch_directml.empty_cache()` + `gc.collect()` |
| `_report_vram(label)` | 向 stderr 打印当前 DML 显存占用（用 `memory_allocated`/`get_device_properties`） |

**查询/卸载接口（供路由调用）：**

| 函数 | 说明 |
|------|------|
| `get_loaded_model() -> str?` | 第一个缓存键的模型 ID |
| `get_loaded_models() -> list[str]` | 缓存中去重后的模型 ID 集合 |
| `unload_model(model_id) -> bool` | 删除该模型全部缓存 pipeline + `_empty_dml_cache()`；无命中返回 False |
| `unload_all_models()` | 清空缓存 + `_empty_dml_cache()` |

**DirectML 兼容补丁函数组**（详见 [06-DirectML兼容与显存管理](./06-DirectML兼容与显存管理.md)）：

| 函数 | 作用 |
|------|------|
| `_patch_nn_embedding(m)` | nn.Embedding 设备不一致时 CPU 计算 |
| `_patch_nn_linear(m)` / `_patched_linear()` | nn.Linear / F.linear 遇 `INTERNAL ASSERT`/`unbox` 错误回退 CPU |
| `_patch_nn_conv2d(m)` | Conv2d 输入对齐权重设备 + CPU 输出搬回 |
| `_patch_nn_groupnorm(m)` | GroupNorm 断言失败回退 CPU |
| `_install_embedding_patch(pipe)` | 对两个文本编码器的全部 Embedding 打补丁（仅一次，模块级锁保证） |
| `_patch_scheduler_step(sched)` | 包装 `set_timesteps`/`step`，对齐 sigmas/alphas 与运行时设备，避免 CPU↔DML 混算崩溃 |

**工具函数：** `_b64_to_image()`、`_image_to_b64()`（JPEG quality=95）、`_get_sd15_cpu_vae(pipe, model_id)`（SD 1.5 VAE 的 CPU fp32 deepcopy 副本，按模型缓存）、`_generate_preview(pipe, latents, is_sdxl, model_id)`（把中间潜变量用缓存的 CPU fp32 VAE 解成 ≤256px JPEG 预览，SDXL/SD1.5 通用）。

**兼容性 shim（模块顶部）：** 在导入 peft/diffusers 前给旧版 transformers 动态补上缺失的 `EncoderDecoderCache`/`DynamicCache` 占位类并 reload，解决 peft≥0.14 与 transformers 4.42 的导入不兼容。

### 6.2 services/lora_manager.py — LoRA 生命周期

**设计：** LoRA 以 PEFT 适配器形式挂载到已缓存的 pipeline 上；**缓存键包含 LoRA 组合**，因此每个组合有独立 pipeline，杜绝适配器残留污染。

**模块级注册表：** `_pipeline_loras: dict[cache_key, set[adapter_name]]`（+ 读写锁），记录每个 pipeline 当前挂载的适配器名集合。

| 函数 | 说明 |
|------|------|
| `_make_key(model_id, mode, loras)` | 生成含 LoRA 组合的稳定缓存键，如 `aom3a1b:txt2img:<1990s,0.6>` |
| `mark_pipeline(pipe, ...)` | 在新 pipeline 上打 `_lora_cache_key` 属性标签并初始化注册表项 |
| `apply_loras(pipe, loras)` | **差异同步**：`delete_adapters` 移除不再需要的 → `load_lora_weights(path, adapter_name=id)` 装载新增（TypeError 时降级为 `weight_name=filename` 形式）→ `set_adapters(names, adapter_weights=weights)` 激活目标组合与权重；`loras` 为空则清空全部适配器 |
| `clear_all_loras(pipe)` | 按注册表移除该 pipeline 全部适配器 |
| `scan_loras()` | 扫描 `{MODELS_DIR}/Lora/` 下 `.safetensors/.pt/.ckpt` 文件，返回元数据（id=文件名去扩展名、size_mb 保留 1 位小数） |

### 6.3 services/model_manager.py — 模型管理

| 函数 | 说明 |
|------|------|
| `peek_checkpoint_type(path)` | **单文件架构探测（不加载模型）**：`.safetensors` 只读 header 的 tensor 名——含 `label_emb`（adaln 单层块）或 `conditioner.embedders.1`（第二文本编码器）判为 SDXL，否则 SD 1.x/2.x；`.ckpt`（pickle）无法廉价探测，回退文件名启发式 |
| `detect_sdxl(model_id, local_path)` | SDXL 判定三级链：名字含 "xl" → 本地目录读 `model_index.json` 的 `_class_name` → 本地文件走 `peek_checkpoint_type`。**修复了原实现"名字猜 SDXL"导致 Anima/Pony/Illustrious 等被误判为 SD 1.5 走全 DML 路径必炸显存的问题** |
| `get_models()` | **合并展示**本地扫描（磁盘就绪/单文件）与 `model_cache` 下载/转换状态；磁盘存在且合法的模型一律视为 ready（修复原实现"下载过一个模型后手动放置的模型从列表消失"）；附带 `settings.default_model` |
| `_scan_local_models()` | 扫描 `MODELS_DIR` 一级条目（跳过 `.` 开头及 `.cache/__pycache__`）：目录以 `model_index.json` 判定为 Diffusers 模型（status=ready）；**文件（`.safetensors`/`.ckpt`）登记为单文件模型（status=single_file，可直接生成）**，若同名 stem 的 Diffusers 目录已存在或正在转换则隐藏。类型统一走 `detect_sdxl` |
| `download_model(model_id, model_type)` | 置 `downloading` 后**立即返回**，`snapshot_download` 在后台任务中执行（原实现同步阻塞 HTTP 请求几十分钟）；完成后更新 `ready` + 实际大小；失败置 `error` |
| `convert_model(model_id)` | **单文件拆包**：置 `converting` 后立即返回，后台用 `DiffusionPipeline.from_single_file()` + `save_pretrained()` 转换为 `{MODELS_DIR}/{文件名去扩展名}/` 的 Diffusers 目录；**保留原文件**；失败置 `error`（源文件重新出现在列表中可重试） |
| `delete_model(model_id)` | 目录 `shutil.rmtree` / 单文件 `unlink` + 清除 `model_cache` 记录 |
| `preload_model(model_id)` | 在线程池调 `generator._warmup_model()`——**真实预热**（加载 + 64×64 推理，shader 编译开销在此付清；原实现只加载不推理，把成本留给首次生图） |

### 6.4 services/history.py — 历史服务

| 函数 | 说明 |
|------|------|
| `add_history(...)` | **先 INSERT 拿自增主键，再按主键命名落盘文件** `{id}.{format}` 与 ≤256px 缩略图 `{id}_thumb.jpg`（quality=80），最后 UPDATE 回填路径；写盘失败回滚记录（修复原实现 `COUNT(*)+1` 推算文件名——删除记录后新图会覆盖旧文件） |
| `get_history(page, page_size)` | 按 `created_at DESC` 分页查询，图片 URL 组装为 `/api/history/{id}/image|thumbnail` 相对路径 |
| `get_history_image(id, thumb)` | 查路径 → 读文件字节；文件缺失返回 None（路由层转 404） |
| `delete_history(id)` | 先删磁盘上的原图与缩略图，再删表记录 |

### 6.5 services/upscaler.py — 超分服务

- **单例管线**：`_load_esrgan_pipeline()` 双重检查锁（DCL）懒加载 `RealESRGANer`（RRDBNet ×4 骨干，`tile=512, tile_pad=10, half=False`），模型权重路径由调用方传入（默认 `RealESRGAN_x4plus`，**权重文件需自备**）。
- **降级策略**：`basicsr`/`realesrgan` 未安装时返回 None，`upscale_image()` 自动降级为 Pillow `LANCZOS` 4 倍放大（功能可用，仅质量下降）。
- `upscale_image(image_data, model_id, tile_size)`：设备优先 DirectML，失败回 CPU；输出 JPEG（quality=95）base64 + 尺寸与耗时统计。

### 6.6 services/test_vram.py — 诊断脚本

独立运行的 VRAM 探测脚本（验证 torch_directml API 可用性），不被任何模块导入。

## 7. 后端模块依赖关系

```
main.py ──► routes/* ──► services/generator.py ──► services/lora_manager.py
   │            │                │                      │
   │            │                └──► config.py         └──► config.py
```

外部依赖：`fastapi`、`uvicorn`、`pydantic`、`aiosqlite`、`torch`、`torch_directml`、`diffusers`、`transformers`、`PIL`、`huggingface_hub`、可选 `peft`/`basicsr`/`realesrgan`/`psutil`/`numpy`。
