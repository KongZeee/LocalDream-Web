# 05 - 数据存储设计

> 返回 [Wiki 首页](./README.md) | 上一章 [04-API接口文档](./04-API接口文档.md) | 下一章 [06-DirectML兼容与显存管理](./06-DirectML兼容与显存管理.md)

项目数据分三处：**SQLite 数据库**（结构化数据）、**outputs 目录**（图片文件）、**models 目录**（模型与 LoRA 权重）。

## 1. 数据目录布局

```
web/backend/data/                    # DATA_DIR（可用 LOCAL_DREAM_DATA_DIR 覆盖）
├── models/                          # MODELS_DIR
│   ├── aom3a1b/                     # SD 1.5 模型（Diffusers 目录结构，须含 model_index.json）
│   │   ├── model_index.json
│   │   ├── text_encoder/
│   │   ├── unet/
│   │   └── vae/
│   ├── counterfeit-v3.0--.../       # HF ID 中 "/" 以 "--" 转义后的目录名
│   ├── anima_v29.safetensors        # 单文件 checkpoint（可直接生成；转换后生成同名 stem 目录）
│   ├── anima_v29/                   # ↑ 由 convert 拆包生成的 Diffusers 目录
│   └── Lora/                        # LoRA 文件目录（固定名称，scan_loras 扫描）
│       ├── 1990s.safetensors
│       └── xxx.pt / xxx.ckpt
├── outputs/                         # OUTPUT_DIR：历史图片落盘
│   ├── 1.jpeg                       # 原图（格式与生图返回一致，默认 jpeg）
│   ├── 1_thumb.jpg                  # 缩略图（≤256px，quality=80）
│   └── ...
└── localdream.db                    # SQLite 数据库（WAL 模式，伴生 -wal/-shm 文件）
```

目录由 `app/config.py` 在导入时自动创建（`makedirs(exist_ok=True)`）。

## 2. SQLite 表结构

数据库连接统一由 [app/db.py](../web/backend/app/db.py) 的 `get_db()` 建立：`aiosqlite` + `Row` 行工厂 + `PRAGMA journal_mode=WAL` + `PRAGMA foreign_keys=ON`。建表脚本在应用 lifespan 启动时由 `init_db()` 执行（幂等，`CREATE TABLE IF NOT EXISTS`）。

### 2.1 `history_items` — 生图历史

| 列 | 类型 | 约束/默认 | 说明 |
|----|------|-----------|------|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | 记录 ID |
| `prompt` | TEXT | NOT NULL | 正向提示词 |
| `negative_prompt` | TEXT | DEFAULT '' | 负向提示词 |
| `seed` | INTEGER | NOT NULL | 使用的种子 |
| `steps` | INTEGER | NOT NULL DEFAULT 20 | 步数 |
| `cfg` | REAL | NOT NULL DEFAULT 7.5 | CFG |
| `width` / `height` | INTEGER | NOT NULL DEFAULT 512 | 分辨率 |
| `model_id` | TEXT | NOT NULL | 模型 ID |
| `scheduler` | TEXT | NOT NULL DEFAULT 'dpm' | 调度器 |
| `mode` | TEXT | NOT NULL DEFAULT 'txt2img' | 生图模式 |
| `image_path` | TEXT | NOT NULL | 原图绝对路径 |
| `thumbnail_path` | TEXT | NULL | 缩略图绝对路径 |
| `created_at` | DATETIME | DEFAULT CURRENT_TIMESTAMP | 创建时间 |

索引：`idx_history_created (created_at DESC)` — 支撑历史页按时间倒序分页查询。

### 2.2 `settings` — KV 设置

| 列 | 类型 | 说明 |
|----|------|------|
| `key` | TEXT PRIMARY KEY | 设置键 |
| `value` | TEXT NOT NULL | 设置值（一律转字符串存储） |

`init_db()` 预置默认行：`default_steps=15`、`default_cfg=7.0`、`default_width/height=512`、`default_scheduler=dpm`、`default_negative_prompt=...`。运行期可通过 `PUT /api/settings` 增改任意键（如 `default_model`）。

### 2.3 `model_cache` — 模型下载缓存

| 列 | 类型 | 说明 |
|----|------|------|
| `model_id` | TEXT PRIMARY KEY | 模型 ID |
| `model_type` | TEXT NOT NULL | `sd15` / `sdxl` |
| `local_path` | TEXT NOT NULL | 本地目录 |
| `size_mb` | INTEGER DEFAULT 0 | 实际大小 |
| `status` | TEXT NOT NULL DEFAULT 'pending' | `downloading` / `converting` / `ready` / `pending` / `error` |
| `preview_path` | TEXT | 预览图（当前未使用） |
| `downloaded_at` | DATETIME | 下载时间（当前未写入） |

> 该表**只在下载/转换过的模型上留痕**（转换的记录以 checkpoint 文件名的 stem 为 model_id）。`GET /api/models` 把本地扫描结果与该表**合并**返回：磁盘上存在且合法的模型一律视为 ready，未完成的下载/转换显示进行中状态，表内记录但磁盘缺失的显示缓存表状态。

## 3. 关键数据流

### 3.1 生图 → 历史落盘

```
SSE complete 事件（先发给客户端）
  └─► routes/generate.py: add_history(prompt, ..., image_b64, "jpeg")
        ├─ INSERT INTO history_items(...) → 拿自增主键 image_id
        ├─ 写 outputs/{id}.jpeg（base64 解码落盘）
        ├─ Pillow 生成 outputs/{id}_thumb.jpg（thumbnail 256px, quality=80）
        └─ UPDATE 回填 image_path / thumbnail_path
             └─ 任一步失败 → DELETE 回滚刚插入的记录（保证表与磁盘一致）
```

### 3.2 历史读取

`GET /api/history` → 按 `created_at DESC` 分页 → 每条组装相对 URL `/api/history/{id}/image|thumbnail`；前端拼接 `api_base_url` 后由 `<img>` 直接加载，图片端点再按 `image_path` 读磁盘字节返回。

### 3.3 历史删除

`DELETE /api/history/{id}` → 先查路径删除原图与缩略图文件 → 再 `DELETE` 表记录。

## 4. 模型目录约定

| 约定 | 说明 |
|------|------|
| 目录名 ↔ model_id | HF repo ID 中的 `/` 在磁盘上以 `--` 存储，如 `runwayml/stable-diffusion-v1-5` ↔ `runwayml--stable-diffusion-v1-5` |
| 合法模型判定 | 目录下存在 `model_index.json`（Diffusers 管线清单）；或顶层存在单文件 checkpoint（`.safetensors`/`.ckpt`，status=single_file） |
| SDXL 判定 | `detect_sdxl` 三级链：model_id 含 "xl" → 目录读 `model_index.json` 的 `_class_name` 含 "XL" → 单文件读 safetensors header key（`label_emb`/`conditioner.embedders.1`） |
| 忽略目录 | `.` 开头目录、`.cache`、`__pycache__` |
| 单文件转换产物 | `POST /api/models/convert` 拆包为同名 stem 目录；转换完成后源文件从模型列表隐藏（文件保留在磁盘） |
| LoRA 目录 | 固定 `{MODELS_DIR}/Lora/`，扫描 `.safetensors` / `.pt` / `.ckpt` |

## 5. 生成参数与设置的存储边界

| 数据 | 存储位置 | 生命周期 |
|------|---------|---------|
| 生图参数当前值 | 前端 `GeneratePage` 本地 state | 会话级 |
| 默认生图参数 | `settings` 表 + 前端 `appStore.settings` | 持久（保存后生效） |
| 后端 API 地址 | `appStore.settings.api_base_url`（保存时亦写入 settings 表） | 持久 + 会话缓存 |
| 已加载模型 | `generator._pipelines`（内存） | 进程级，重启即失效 |
| 预热标记 | `generator._warmed_up`（内存） | 进程级 |
| LoRA 挂载状态 | `lora_manager._pipeline_loras`（内存） | 随 pipeline 生命周期 |
