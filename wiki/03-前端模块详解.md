# 03 - 前端模块详解

> 返回 [Wiki 首页](./README.md) | 上一章 [02-后端模块详解](./02-后端模块详解.md) | 下一章 [04-API接口文档](./04-API接口文档.md)

前端位于 `web/src/`，是 React 18 + TypeScript 的 Vite SPA。状态管理用 Zustand，样式用 TailwindCSS（自定义 neon 赛博朋克暗色主题），路由用 React Router 7。

## 模块总览

| 模块 | 路径 | 职责 |
|------|------|------|
| 入口 | `src/main.tsx` | 挂载 React 根组件、引入全局样式 |
| 路由 | `src/App.tsx` | 定义 5 条路由（Layout 嵌套） |
| 状态 | `src/stores/appStore.ts` | Zustand 全局状态（模型/LoRA/设置/UI） |
| 请求 | `src/utils/api.ts` | 全部后端 API 封装 + SSE 流解析 |
| 布局 | `src/components/Layout.tsx` | 侧边栏 + 内容区骨架 |
| 导航 | `src/components/Sidebar.tsx` | 顶部品牌、导航项、折叠、状态栏 |
| 状态栏 | `src/components/StatusBar.tsx` | GPU/CPU 内存实时监控（5s 轮询） |
| 页面 | `src/pages/*.tsx` | 模型管理 / 生图 / 历史 / 超分 / 设置 |
| 工具 | `src/lib/utils.ts`、`src/hooks/useTheme.ts` | `cn()` 类名合并；明暗主题 Hook（未启用） |

---

## 1. main.tsx 与 App.tsx

**main.tsx**：`createRoot` 渲染 `<StrictMode><App /></StrictMode>`，加载 `index.css`（Tailwind 指令 + 全局暗色样式）。

**App.tsx 路由表：**

```tsx
<Router>
  <Routes>
    <Route element={<Layout />}>
      <Route path="/" element={<ModelListPage />} />
      <Route path="/generate" element={<GeneratePage />} />
      <Route path="/generate/:modelId" element={<GeneratePage />} />
      <Route path="/history" element={<HistoryPage />} />
      <Route path="/upscale" element={<UpscalePage />} />
      <Route path="/settings" element={<SettingsPage />} />
    </Route>
  </Routes>
</Router>
```

- `/generate/:modelId` 路由参数允许从模型管理页直接跳转并锁定目标模型。
- `Home.tsx` 是空占位组件，未被路由引用。

## 2. stores/appStore.ts — 全局状态（Zustand）

单 store 设计，通过 `create<AppState>()` 创建，组件用 `useAppStore()` 或选择器订阅。

### 2.1 数据模型（TypeScript 接口）

| 接口 | 字段 | 说明 |
|------|------|------|
| `ModelInfo` | `id, name, type: 'sd15'\|'sdxl', status: 'ready'\|'downloading'\|'converting'\|'single_file'\|'error', size_mb, preview_url` | 模型元数据（`single_file` 可直接生成；`converting` 为后台拆包中） |
| `LoraInfo` | `id, name, filename, path, size_mb` | LoRA 文件元数据（与后端 scan_loras 对齐） |
| `ActiveLora` | `lora: LoraInfo, weight: number` | 已激活 LoRA + 权重 |
| `GenerationParams` | prompt/负向/mode/steps/cfg/seed/width/height/scheduler/denoise_strength/show_preview/preview_stride/image/mask/speed_mode | 生图参数快照（定义用，页面实际用本地 useState） |
| `AppSettings` | `api_base_url`（默认 `http://127.0.0.1:8081`）、默认步数/CFG/尺寸/调度器/负向词/速度档 | 用户设置（与后端 settings 表同步） |

### 2.2 状态字段与 Actions

| 类别 | 字段 / Action | 说明 |
|------|--------------|------|
| UI | `sidebarCollapsed` / `toggleSidebar()` | 侧边栏折叠态 |
| 模型 | `models` / `setModels()` | 全局模型列表 |
| 模型 | `selectedModelId` / `setSelectedModelId()` | 当前选中（待生成）模型 |
| 模型 | `loadedModelId` / `setLoadedModelId()` | 后端显存中已加载模型（5s 轮询更新） |
| 设置 | `settings` / `setSettings(partial)` | 浅合并更新 |
| LoRA | `loras` / `setLoras()` | 可用 LoRA 列表 |
| LoRA | `activeLoras` / `addActiveLora(lora, weight=0.7)`（去重）、`removeActiveLora(id)`、`updateLoraWeight(id, w)`、`clearActiveLoras()`、`setActiveLoras()` | 已选 LoRA 组合管理 |

> 生图参数本身**不在** store 中——`GeneratePage` 用本地 `useState` 管理（默认值来自 `settings`），只有跨页面共享的信息进 store。

## 3. utils/api.ts — 请求层

### 3.1 基础设施

- `getBaseUrl()`：每次请求前从 store 读取 `settings.api_base_url`（运行时可改，无需重建模块）。
- `request<T>(path, options)`：统一 JSON 请求封装——自动拼 baseUrl、设 `Content-Type`、非 2xx 时解析错误体抛 `Error(message|detail)`。

### 3.2 SSE 流式解析 — `generateImage()`

生图接口的专用函数，签名：

```ts
export function generateImage(
  params: GenerateRequest,
  onProgress: (event: SSEProgressEvent) => void,
  onComplete: (event: SSECompleteEvent) => void,
  onError: (error: string) => void,
  onNotice?: (message: string) => void,   // 可选：OOM 降级/排队等非致命提示
): AbortController
```

实现要点：

1. `fetch POST /api/generate`（非 EventSource，因为需要 POST body）
2. 手动 `response.body.getReader()` + `TextDecoder` 增量读取，按 `\n` 切行、保留残包 `buffer`
3. 解析 `data: ` 前缀的 JSON 行，按 `type` 分发回调：
   - `started` → 转成一次 `step: 0` 的 progress
   - `progress` → `onProgress`（含可选 `image` 中间预览）
   - `notice` → `onNotice`（GPU 排队 / OOM 降级提示）
   - `complete` → `onComplete`
   - `error` → `onError`
4. 返回 `AbortController`，页面「停止」按钮调用 `abort()` 中断（AbortError 静默，不触发 onError）
5. 解析失败的行直接跳过（容错）

### 3.3 SSE 事件类型（与后端契约）

```ts
SSEStartedEvent   { type: 'started'; total_steps }
SSEProgressEvent  { type: 'progress'; step; total_steps; image?; preview_format? }
SSENoticeEvent    { type: 'notice'; message }
SSECompleteEvent  { type: 'complete'; image; format; seed; width; height;
                    generation_time_ms; first_step_time_ms; total_steps }
                    // width/height 为实际输出尺寸（OOM 降级时可能小于请求值）
SSEErrorEvent     { type: 'error'; message }
```

### 3.4 其余 API 函数一览

| 函数 | 端点 | 说明 |
|------|------|------|
| `fetchHealth()` | `GET /api/health` | 设置页健康检查 |
| `fetchModels()` | `GET /api/models` | 模型列表 + 默认模型（含 single_file/converting 状态） |
| `downloadModel(id, type)` | `POST /api/models/download` | HF 下载（后台执行，立即返回） |
| `convertModel(id)` | `POST /api/models/convert` | 单文件 checkpoint 转 Diffusers（后台执行） |
| `deleteModel(id)` | `DELETE /api/models/{id}` | 删除模型（目录或单文件） |
| `fetchLoadedModels()` | `GET /api/models/loaded` | 已加载模型（生图页 5s 轮询） |
| `unloadModel(id)` / `unloadAllModels()` | `POST /api/models/unload[-all]` | 卸载 |
| `preloadModel(id)` | `POST /api/models/{id}/preload` | 预加载（含真实预热） |
| `fetchHistory(page, size)` | `GET /api/history` | 分页历史 |
| `deleteHistoryItem(id)` | `DELETE /api/history/{id}` | 删除历史 |
| `fetchLoras()` / `fetchLoraNames()` | `GET /api/loras[/names]` | LoRA 列表 |
| `upscaleImage(file, modelId, tileSize?)` | `POST /api/upscale` | multipart 上传放大 |
| `fetchSystemStatus()` | `GET /api/system/status` | 状态栏轮询 |
| `fetchSettings()` / `saveSettings(dict)` | `GET/PUT /api/settings` | 设置读写 |

## 4. components/ — 公共组件

### Layout.tsx
全屏 flex 布局：左侧 `Sidebar` + 右侧滚动内容区（`<Outlet />`），顶部一条渐变霓虹装饰线，内容区带 fade-in 动画。

### Sidebar.tsx
- 导航项：`/` 模型管理（Box）、`/generate` 图像生成（Image）、`/history` 历史记录（History）、`/upscale` 超分辨率（Zap）、`/settings` API 设置（Settings）。
- 高亮逻辑：精确匹配 `/` 或前缀匹配其它路径。
- 折叠态宽 16（w-16）/展开 56（w-56），带过渡动画；底部内嵌 `StatusBar` 与「在线」指示灯。

### StatusBar.tsx
- 挂载时 `fetchSystemStatus()` + `setInterval` **每 5 秒轮询**。
- 渲染：当前加载模型名、GPU 显存进度条、CPU 内存进度条；占用率 <60% 青色、<85% 黄色、其余红色；数值格式化 MB/GB。

### Empty.tsx
占位空组件（`cn()` 包裹居中文本），当前无引用。

## 5. pages/ — 页面详解

### 5.1 GeneratePage.tsx — 生图主界面（最复杂页面）

**布局**：左侧 320px 参数面板（可滚动）+ 右侧自适应预览区。

**状态组成：**

- 模型相关：`switchingModel`、`preloadingModel`（来自 URL 参数或 store 的 `modelId`）
- 生图参数（useState × 12）：`mode`、`prompt`、`negativePrompt`、`steps`、`cfg`、`seed`（-1 为随机）、`width/height`、`scheduler`、`speedMode`、`denoiseStrength`、`showPreview`、`previewStride`
- img2img/inpaint 输入：`imageBase64/imagePreview`、`maskBase64/maskPreview`（支持点击与拖拽上传，`fileToBase64` 去掉 dataURL 前缀）
- 生成过程：`generating`、`currentStep/totalSteps`、`intermediateImage`、`finalImage/finalFormat`、`generationTime`、`error`、`notice`（黄色提示条：GPU 排队 / OOM 降级）、`resultWidth/resultHeight`（实际输出尺寸，OOM 降级时与请求值不同）、`abortRef`

**副作用（useEffect）：**

1. 每 5 秒轮询 `fetchLoadedModels()` 刷新 `loadedModelId`
2. 挂载时 `fetchLoras()` 拉取 LoRA 列表

**核心交互：**

| 操作 | 行为 |
|------|------|
| 速度档切换 | `handleSpeedModeChange` 同步覆写 steps/cfg/scheduler（前端镜像后端 SPEED_PRESETS） |
| 模型切换 | 若已加载其它模型 → 先 `unloadModel` 释放显存 → `navigate(/generate/{newId})` |
| 预加载 | `preloadModel()` 后刷新 loadedModelId；已加载时按钮显示「已预加载」 |
| 开始生成 | `handleGenerate`：`seed=-1` 时取随机数；组装 `GenerateRequest`（含 activeLoras 映射）；调 `generateImage()`（传入 onNotice 回调），progress 更新步骤与预览图，complete 展示结果、回填实际 seed 并记录实际输出尺寸 |
| 停止 | `abortRef.current.abort()` 中断 SSE |
| 下载 | 结果图以 `data:` URL 直接触发 `<a download>` |

**子组件 `ParamSlider`**：受控滑块（label/value/min/max/step/onChange），用于步数/CFG/去噪强度/预览间隔。

### 5.2 ModelListPage.tsx — 模型管理

- 挂载即 `fetchModels()`；卡片网格展示模型（预览图占位、类型徽标、大小、状态图标）。
- **后台任务轮询**：列表中存在 `downloading` / `converting` 状态时每 5 秒静默刷新（`loadModels(silent)` 不触发整页 loading）。
- 「添加模型」：展开表单输入 HF 模型 ID + 类型（sd15/sdxl）→ `downloadModel()` **立即返回**，下载在后台执行、由轮询观察进度。
- **单文件模型**：status 为 `single_file` 的卡片可直接点击生成（后端 `from_single_file` 直载）；卡片上有「转换」按钮（FileCog 图标）→ `convertModel()` 后台拆包为 Diffusers 目录（状态 `converting` → `ready`）。
- 卡片操作：点击就绪/单文件模型 → 选中并跳转 `/generate/{id}`；「卸载」按钮（已加载时显示）→ `unloadModel()`；删除 → `deleteModel()`（目录或单文件）。

### 5.3 HistoryPage.tsx — 历史记录

- `page` 变化触发 `fetchHistory(page, 20)`；缩略图网格（2~5 列响应式）。
- 图片 URL 拼接：`{api_base_url}{item.thumbnail_url}`（后端返回相对路径）。
- 点击缩略图 → 详情弹层（大图 + 完整参数：提示词/种子/步数/CFG/尺寸/模型/调度器/模式/时间）。
- 删除单条 → `deleteHistoryItem()` 后重载当前页；分页器（ChevronLeft/Right）。

### 5.4 UpscalePage.tsx — 超分辨率

- 左右两栏：原图拖拽/点击上传区 + 结果区。
- 参数：放大模型名（默认 `RealESRGAN_x4plus`）与 tile size（512）。
- `upscaleImage(file, model, tile)` → 结果以 base64 data URL 展示，附耗时与输出尺寸，可下载。

### 5.5 SettingsPage.tsx — API 设置

- 「后端状态」卡片：`fetchHealth()` 展示 status/GPU/已加载模型。
- 表单：`api_base_url`、默认步数/CFG/宽高/调度器/负向提示词/速度档；加载时 `fetchSettings()` 与本地默认合并；保存调 `saveSettings()` 并同步进全局 store（带 saved/error 状态反馈）。

### 5.6 Home.tsx
空占位组件，未被路由使用。

## 8. 前端模块依赖关系

```
main.tsx ──► App.tsx ──► Layout.tsx ──► Sidebar.tsx ──► StatusBar.tsx
    │            │                              │
    │            ├──► ModelListPage ─┐          └──► appStore.ts ◄──┐
    │            ├──► GeneratePage ──┼──► utils/api.ts ────────────┤
    │            ├──► HistoryPage ───┤        （读 api_base_url）    │
    │            ├──► UpscalePage ───┤                               │
    │            └──► SettingsPage ──┴──────────────────────────────┘
```
