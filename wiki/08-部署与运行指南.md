# 08 - 部署与运行指南

> 返回 [Wiki 首页](./README.md) | 上一章 [07-依赖关系](./07-依赖关系.md)

## 1. 系统要求

| 项目 | 最低要求 | 推荐配置 |
|------|---------|---------|
| 操作系统 | Windows 10/11 | Windows 11（部分兜底逻辑依赖 Win32 API） |
| GPU | AMD RX 5700 XT (8GB)+ | AMD RX 6800 XT (16GB)+ |
| 显存 | 8GB | 16GB+ |
| 内存 | 16GB | 32GB |
| Python | 3.11 / 3.12 | 3.12 |
| Node.js | 18+ | 20+ |

- **NVIDIA 用户**：代码含 CUDA 探测分支，理论上把 `torch-directml` 换成 CUDA 版 PyTorch 可适配，但本项目只在 AMD + DirectML 场景测试过。
- **Linux/macOS**：核心生图依赖 torch-directml（Windows 专属），无法直接运行 GPU 路径。

## 2. 安装步骤

### 2.1 获取代码

```bash
git clone https://github.com/<你的用户名>/LocalDream-Web.git
cd LocalDream-Web
```

### 2.2 安装后端依赖（建议虚拟环境）

```bash
python -m venv .venv
.venv\Scripts\activate        # Windows

pip install torch torch-directml fastapi uvicorn aiosqlite diffusers transformers accelerate safetensors pillow peft
```

可选增强包：

```bash
pip install huggingface-hub psutil numpy            # 模型下载 / 内存统计 / 超分数组
pip install basicsr realesrgan                      # RealESRGAN 真超分（缺省自动降级 LANCZOS）
```

版本要求：`torch>=2.0.0`、`torch-directml>=0.2.0`、`fastapi>=0.100.0`、`uvicorn>=0.20.0`、`aiosqlite>=0.19.0`、`diffusers>=0.25.0`、`transformers>=4.30.0`、`accelerate>=0.20.0`、`peft>=0.5.0`。

> 兼容提示：若使用旧版 transformers（如 4.42）配新版 peft，generator.py 已内置 `EncoderDecoderCache` 导入 shim；另有 `_patch_transformers.py` 可修复本机 transformers 的 safetensors metadata 崩溃（需改成你的安装路径后手动运行一次）。

### 2.3 安装前端依赖

```bash
cd web
npm install
```

### 2.4 准备模型文件

支持三种形态，放入 `web/backend/data/models/`：

```
web/backend/data/models/
├── aom3a1b/                  ← Diffusers 目录（内含 model_index.json）
├── anima-2.9b/               ← 名字不含 "xl" 的 SDXL 目录也 OK（按 model_index.json 识别）
├── anima_v29.safetensors     ← 单文件 checkpoint（可直接生成，也可一键拆包）
└── Lora/                     ← LoRA 文件（.safetensors / .pt / .ckpt）
```

- HF repo ID 中的 `/` 存盘时写成 `--`（如 `runwayml--stable-diffusion-v1-5`）
- 也可以不手动下载：启动后在「模型管理 → 添加模型」输入 HF 模型 ID 在线下载（**后台执行**，列表中轮询进度即可）
- **单文件模型（.safetensors/.ckpt）**：放进目录即出现在列表（状态「单文件」），可直接点击生图；建议点卡片上的「转换」按钮拆包为 Diffusers 目录（后台执行，之后加载显著变快）
- SDXL 首次生图会额外从 HF 拉取 `madebyollin/sdxl-vae-fp16-fix` VAE 权重

## 3. 启动方式

### 方式一：一键脚本（Windows，推荐）

双击根目录 **`start.bat`** 或命令行执行：

```cmd
start.bat
```

脚本行为：先杀掉 8081/5173 端口残留进程 → 启动后端（`web\backend\python run.py`）→ 等 5 秒 → 启动前端（`web\npm run dev`）。

停止：运行 **`stop.bat`**（杀掉 8081/5173 端口进程）。

> `web/start.bat` 是另一版启动脚本：为后端/前端各开一个独立 cmd 窗口，便于分别观察日志。

### 方式二：手动分终端启动（开发联调）

```bash
# 终端 1：后端
cd web/backend
python run.py

# 终端 2：前端
cd web
npm run dev
```

启动成功后：

| 服务 | 地址 |
|------|------|
| 前端界面 | <http://localhost:5173> |
| 后端 API | <http://127.0.0.1:8081>（局域网：`http://<本机IP>:8081`） |
| 健康检查 | `GET http://127.0.0.1:8081/api/health` |

> 前端 dev server 监听 `0.0.0.0:5173`、后端 CORS 全开，局域网内其它设备可将前端「API 设置」中的地址改为 `http://<后端机IP>:8081` 直接使用。

### 方式三：生产构建

```bash
cd web
npm run build        # tsc -b && vite build，产物在 web/dist/
```

用任意静态服务器托管 `dist/`（注意把 API 请求指向后端地址），后端仍需 `python run.py` 运行。

## 4. 环境变量配置

启动后端前设置（Windows `set` / PowerShell `$env:`）：

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `LOCAL_DREAM_DATA_DIR` | `web/backend/data` | 数据根目录 |
| `LOCAL_DREAM_MODELS_DIR` | `{DATA_DIR}/models` | 模型目录 |
| `LOCAL_DREAM_OUTPUT_DIR` | `{DATA_DIR}/outputs` | 输出图片目录 |
| `LOCAL_DREAM_DB_PATH` | `{DATA_DIR}/localdream.db` | SQLite 路径 |
| `LOCAL_DREAM_HOST` | `0.0.0.0` | 后端监听地址 |
| `LOCAL_DREAM_PORT` | `8081` | 后端端口 |
| `LOCAL_DREAM_MAX_PIPELINES` | `2` | LRU 缓存的 pipeline 数上限（16GB+ 显卡可调到 3~4） |

示例：

```cmd
set LOCAL_DREAM_PORT=9090
set LOCAL_DREAM_MODELS_DIR=D:\SD-Models
python web/backend/run.py
```

> 改后端端口后，记得同步修改前端「API 设置」页的 `api_base_url`（默认 `http://127.0.0.1:8081`）。

## 5. 首次使用建议流程

1. 打开 <http://localhost:5173> → 「模型管理」确认模型被识别（状态：就绪）
2. 点击模型卡片 → 跳转「图像生成」页
3. 点「预加载模型」提前装载（首次加载 + 预热较慢，完成后生图显著变快）
4. 输入提示词 → 选择速度档（快速/标准/高质量）→ 开始生成
5. 需要风格叠加时在「LoRA」区添加并调权重
6. 生成结果自动进入「历史记录」；需放大时用「超分辨率」页上传 4x 放大

## 6. 显存不足应对

手动手段（按优先级）：

1. 降低分辨率（1024×1024 → 512×512）
2. 用「快速」速度档（10 步）
3. 减少同时启用的 LoRA 数量
4. 在「模型管理」卸载不用的模型（LRU 上限默认 2 个 pipeline，可用 `LOCAL_DREAM_MAX_PIPELINES` 调整）
5. 关闭其它占显存程序

后端已内置（自动，无需干预）：

- **OOM 分级降级阶梯**：清缓存+卸载其它模型 → 关闭实时预览 → txt2img 自动降分辨率（每级通过 SSE `notice` 事件提示，生图不中断）
- **GPU 推理串行化**：并发请求自动排队（避免并发推理必炸显存）
- VAE slicing/tiling、attention slicing、LRU 逐出（逐出后真正归还显存给驱动）
- 全部手段用尽仍 OOM 时 SSE 返回可操作的 `error` 提示

## 7. 常见问题排查

| 现象 | 原因与处理 |
|------|-----------|
| 前端请求全部失败 | 后端未启动 / 端口不一致 → 检查「API 设置」`api_base_url` 与 `LOCAL_DREAM_PORT` |
| 模型列表为空 | Diffusers 目录缺少 `model_index.json`；或 `LOCAL_DREAM_MODELS_DIR` 指向错误。单文件模型须为 `.safetensors`/`.ckpt` 且位于模型目录**顶层** |
| 首次生图极慢 | pipeline 冷加载 + 预热 + shader 编译，属正常；可先「预加载」（预加载即执行真实预热推理） |
| 单文件模型每次加载都慢 | `from_single_file` 直载每次都要在内存转换——点模型卡片上的「转换」按钮拆包为 Diffusers 目录 |
| 生成中出现黄色提示条 | SSE `notice` 事件：GPU 排队或 OOM 自动降级（关预览/降分辨率）的告知，生图仍在继续，无需处理 |
| 结果图比请求的分辨率小 | OOM L3 降级（分辨率 ×0.75 重试成功），`complete` 事件的 width/height 为实际输出尺寸 |
| SDXL 生图报 VAE 相关错误 | 首次需联网拉取 `sdxl-vae-fp16-fix`；确认网络或提前手动放入 HF 缓存 |
| RDNA 1 上 `INTERNAL ASSERT`/`unbox` 报错 | 已由算子补丁自动 CPU 回退；若仍出现，查看后端控制台 `[Generator] ... fallback` 日志定位 |
| 状态栏 GPU 数值不像显存 | DirectML 无显存查询 API，显示的是系统内存（Win32 兜底），仅 CUDA 下为真实显存 |
| 端口被占用 | `start.bat` 会自动清理；手动场景用 `stop.bat` 或自行杀进程 |

## 8. 开发常用命令

```bash
# 前端
cd web
npm run dev          # 开发服务器
npm run check        # tsc 类型检查（不产出）
npm run lint         # ESLint
npm run build        # 生产构建

# 后端
cd web/backend
python run.py        # 启动 API（uvicorn, 日志级别 info）
python -m app.services.test_vram   # VRAM 探测诊断（可选）
```

## 9. SillyTavern 插件（可选）

根目录 `LocalDream-SD.json` 是 SillyTavern「酒馆助手」脚本插件（v1.1），导入后可在酒馆聊天中通过 `<local_img>提示词</local_img>` 标签或「🎨 SD生图」按钮调用本项目后端生图（默认连 `127.0.0.1:8000`，在插件设置中改为 8081）。插件自带配置面板、IndexedDB 图库与悬浮球，与主项目共用同一套 `/api/*` 接口。
